# v0.4.0 — Hardening + simplification pass

**Date:** 2026-07-02
**Status:** Approved
**Scope:** Module `ppdm2Jira/` (source + tests), example configs, and the docs that describe the
changed behaviour. No new features; no change to the error-handling model (per-instance isolation,
watermark advanced only on full instance success).

## Context

A whole-codebase review (all 52 Pester tests green at baseline, v0.3.0) found two behavioural gaps,
two smaller correctness inconsistencies, and a set of duplication/robustness cleanups. This spec
fixes the full set in one pass. The architecture is unchanged: PpdmClient → Normalizer → Router →
Dedup/JiraClient → StateStore, orchestrated by `Invoke-ppdm2JiraSync`.

## 1. Watermark correctness (design-level change)

**Problem.** Activities are queried with `startTime ge <watermark>` but the watermark advances to
the max `occurredAt`, which for activities prefers `endTime` and is also pushed forward by alert
`postedTime`. A job that starts before the watermark and finishes (fails) after the pass never
matches a later `startTime ge` filter: the failure is permanently missed. Additionally, activities
use `ge` while alerts use `gt` — the `gt` side can miss a same-second alert, while replays are
already idempotent via Jira-search dedup (ADR-0003), so misses are the only dangerous direction.

**Fix — filter on visibility time, add a skew overlap:**

- `Get-ppdm2JiraFailedBackups` (`Private/PpdmClient.ps1`): filter becomes
  `result.status in (…) and endTime ge "<since>" and parentId ne null and classType in ("JOB","JOB_GROUP") and category in (…)`.
  An activity becomes eligible exactly when it gets an `endTime` — the same field the watermark
  advances on. Update the comment-based help (`.PARAMETER Since`: jobs with **endTime** >= this).
- `Get-ppdm2JiraAlerts`: `postedTime gt` → `postedTime ge` (consistency; replay-safe). Update its
  `.PARAMETER Since` help the same way (alerts with postedTime >= this).
- **Overlap:** the orchestrator subtracts `queryOverlapMinutes` (new optional settings key,
  default **5**, integer >= 0) from the watermark before calling the getters:
  `$since = $wm.AddMinutes(-$overlap)`. The overlap lives **only** in the orchestrator; the getters
  stay pure wrappers that query exactly the `-Since` they receive. `$maxOccurred` keeps starting at
  `$wm` (not `$since`) so the watermark never moves backwards.
- `endTime` exists on the Activity model in `docs/swagger/9765-20.1.0.json` (string, date-time).
  Whether the live API accepts it as a filter field joins **M0 open item #1**;
  `scripts/Test-ppdm2JiraPpdmConnection.ps1` exercises the exact production filter unchanged, so M0
  validates it for free.

## 2. JiraClient hardening (`Private/JiraClient.ps1`)

- **PS7 TLS opt-out actually works.** `Invoke-ppdm2JiraHttp` currently toggles
  `ServicePointManager.ServerCertificateValidationCallback`, which PS7's `Invoke-WebRequest`
  (HttpClient-based) ignores — `tlsValidate = $false` silently does nothing on PS7. Branch on
  `$PSVersionTable.PSEdition`: on `Core`, pass `-SkipCertificateCheck` to `Invoke-WebRequest`; keep
  the callback swap only for Desktop (5.1). Keep the existing `Write-Warning` on every skip.
- **Dispose in the 5.1 error path:** wrap the `HttpWebResponse`/`StreamReader` reads in
  `try/finally` with `.Dispose()`.
- **Typed flavour check.** `New-ppdm2JiraClient` adds `apiVersion = [int]$Config.apiVersion` to the
  client object. `Find-ppdm2JiraOpenIssue` replaces `$Client.apiBase -like '*api/3'` with
  `$Client.apiVersion -eq 3` and collapses the duplicated search bodies: build one common body
  (`jql`, `fields`, `maxResults = 1`); v3 posts to `/search/jql`, v2 adds `startAt = 0` and posts to
  `/search`.
- **Validate `bodyFormat` at construction.** Same pattern as `authMode`: accept `'adf'` or
  `'wiki'`, otherwise throw `"Unknown bodyFormat '…' (expected 'adf' or 'wiki')."` (today a typo
  silently sends a plain string to a v3 API and surfaces as a confusing Jira 400).
- Hoist the `$retryable` array above the retry loop in `Invoke-ppdm2JiraRequest`.
- **New private helper `New-ppdm2JiraIssueWithLink`** (lives here, next to the operations it
  composes): takes `Client`, `Target`, `Incident`, `InstanceId`; creates the issue, sets the remote
  link (globalId = sanitised dedupKey, url = `ppdmLinks.deepLink`, title
  `'PPDM <instanceId> <ppdmLinks.id>'`), returns the new key. Used by **both** orchestrator create
  paths (see §3).

## 3. Orchestrator fixes (`Public/Invoke-ppdm2JiraSync.ps1`)

- **Remote link on every create.** The `created(404-fallback)` path currently skips the remote
  link. Both the Create path and the 404-fallback call `New-ppdm2JiraIssueWithLink` (§2), removing
  the inconsistency and the duplication.
- **Traceable recurrence comment.** Replace `"Recurred at <sync wall-clock>"` with
  `'Recurred at {0} — event {1}' -f (Format-ppdm2JiraTimestamp <occurredAt>), <dedupKey>`, falling
  back to the current UTC time only when `occurredAt` is null.
- **Fail-fast config validation.** New `Private/Config.ps1` with `Assert-ppdm2JiraSettings`:
  validates the parsed settings **before any instance is touched** and throws one aggregated,
  operator-readable error listing every problem. Required: `stateDir`, `routingPath`,
  `jira.{baseUrl, authMode, bodyFormat, apiVersion, secretName}`, non-empty `instances` each with
  `{id, baseUrl, secretName}`. Optional: `queryOverlapMinutes` (integer >= 0). Called by
  `Invoke-ppdm2JiraSync` right after `Import-PowerShellDataFile`.
- **Folder convention restored.** `Connect-ppdm2JiraInstance` moves to `Private/PpdmClient.ps1`
  (PPDM-session concern; keep its suppression attribute + justification comment).
  `Write-ppdm2JiraLog` moves to a new `Private/Logging.ps1`, **stops returning the line**, and the
  four `| Out-Null` call sites drop the pipe. `Public/Invoke-ppdm2JiraSync.ps1` then contains only
  the exported function.

## 4. Cross-cutting simplifications

- **One owner for the timestamp format.** `Format-ppdm2JiraTimestamp` (PpdmClient.ps1) is the only
  place `yyyy-MM-ddTHH:mm:ssZ` appears; the orchestrator comment path and
  `Set-ppdm2JiraWatermark` reuse it. (The deliberately-fixed `HH`-vs-`hh` upstream bug lives in
  this string — single source of truth.)
- **PpdmClient helpers** (both private, in `Private/PpdmClient.ps1`):
  - `ConvertTo-ppdm2JiraQuotedList([string[]])` → `'"a","b"'` — replaces the four inline
    `($x | ForEach-Object { '"{0}"' -f $_ }) -join ','` sites.
  - `Get-ppdm2JiraPpdmBaseUrl` → wraps
    `Get-Variable -Name 'PPDM_API_BaseUri' -Scope Global -ValueOnly -ErrorAction SilentlyContinue`;
    used as the `$PpdmBaseUrl` parameter default in `Get-ppdm2JiraFailedBackups`,
    `Get-ppdm2JiraAlerts`, and `ConvertTo-ppdm2JiraIncident` (Normalizer).
- **StateStore robustness** (`Private/StateStore.ps1`):
  - Read: replace `ParseExact` with `([datetimeoffset]::Parse($wmString,
    [Globalization.CultureInfo]::InvariantCulture)).UtcDateTime` (no manual `Z` strip) — tolerates
    fractional seconds and hand-edited variants, still throws loudly on garbage. In the
    already-a-datetime branch, only `SpecifyKind Utc` when `Kind -eq 'Unspecified'`; otherwise
    `ToUniversalTime()` (never relabel a Local time as UTC).
  - Write: use `Format-ppdm2JiraTimestamp`.
- **Router** (`Private/Router.ps1`):
  - **Drop `assigneeGroup`** from the resolved target — nothing consumes it (Jira create takes a
    user assignee, not a group; YAGNI). This amends the documented target shape — see §5 docs.
  - Category label reuses the sanitiser:
    `'cat_{0}' -f (ConvertTo-ppdm2JiraLabel ($category.ToString().ToLower()))`.
- **Deliberate non-change:** the psm1 dynamic export stays as-is (the manifest already pins
  exports; not worth diff noise).

## 5. Tests, docs, versioning

**Tests (Pester, no live systems; mock PPDM-pwsh cmdlets and `Invoke-ppdm2JiraHttp` /
`Invoke-WebRequest` as today).** Every behaviour change gets an assertion:

- PpdmClient: filter strings assert `endTime ge` (activities) and `postedTime ge` (alerts).
- Orchestrator: overlap arithmetic (`-Since` = watermark − `queryOverlapMinutes`; default 5 when
  the key is absent); watermark still starts from `$wm`; 404-fallback creates carry a remote link;
  recurrence comment contains the incident's `occurredAt` and `dedupKey`.
- JiraClient: `New-ppdm2JiraClient` throws on bad `bodyFormat`; client object exposes
  `apiVersion`; v2 vs v3 search path/body selection; on PS7 (`PSEdition Core`) a `tlsValidate =
  $false` client passes `-SkipCertificateCheck` to `Invoke-WebRequest` (mock in module scope).
- Config: `Assert-ppdm2JiraSettings` aggregates multiple missing-key errors into one message;
  passes on a valid settings shape.
- StateStore: fractional-second watermark string parses; round-trip still green.
- Router: target no longer has `assigneeGroup`; category label sanitised via the shared helper.
- Update existing fixtures/tests that reference `assigneeGroup` (`tests/Router.Tests.ps1`).

**Docs (docs are the contract — they move in lockstep):**

  target shape without `assigneeGroup`.
- `docs/adr/ADR-0004-config-driven-routing.md`: **amendment note** (dated 2026-07-02): target shape

  `ppdm2Jira/config/routing.psd1.example`: drop `assigneeGroup`.
- `CLAUDE.md`: open validation item #1 gains "endTime as an activities filter field".
- `CHANGELOG.md`: 0.4.0 entry (fixed / changed / removed).

**Versioning:** `ppdm2Jira.psd1` → `0.4.0` (behaviour changes: filter fields, comment content,

## Non-goals

- No change to the Incident model, routing rule matching, dedup/correlation logic, or the
  per-instance error-isolation model.
- No Jira write-back, no INFORMATIONAL alerts, no fleet scaling (ADR-0002/0005 unchanged).
- No live-system validation in this pass (M0 scripts remain the validation vehicle).

## Conventions that bind the implementation

- Windows PowerShell 5.1 compatible (no `??`, `?.`, ternary); `Set-StrictMode -Version Latest`
  safe — optional-field reads via `Get-ppdm2JiraProp`.
- Tests mock `PPDM-pwsh` cmdlets and `Invoke-ppdm2JiraHttp`/`Invoke-WebRequest`, never live HTTP;
  private functions reached via `InModuleScope ppdm2Jira`.
- Run `pwsh ./ppdm2Jira/tests/Run-AllTests.ps1` (must be fully green) and
  `Invoke-ScriptAnalyzer -Path ./ppdm2Jira -Recurse` (no new findings; keep justified
  suppressions).
